# 论证拆解（Argument Decomposition）

把原论证重构为可追溯、可检查的命题和支持关系。依次优先考虑忠实性（Fidelity）、最小性（Minimality）和可追溯性（Traceability）。以待拆解文本为首要证据。上下文和作者其他著作可用于辅助诠释，是否实际参与当前推导须有独立证据。遵守用户限定的材料范围。默认呈现语义问题、推理缺口及支持程度，评价前提真假、反驳、强化或修复论证仅在用户要求时另行进行。

## 拆解流程（Decomposition Workflow）

1. **识别目标（Identify the Objective）**。找出作者试图确立的结论和各自的支持路线。区分作者主张、引述、反方观点和设想，以及作为实质证据的例证与纯修辞。只有主张时，记录该主张及缺少推论依据的状态。复杂论证按实际目标组织子论证，保留独立路线和可追溯的原文位置。
2. **明确定义（Clarify Definitions）**。仅为实质影响推导的术语列 `D1`、`D2`。保留作者定义及其问题。若定义本身是待建立的主张，在得出时列为 `C`。对未精确定义的术语，列出文本支持的最小共同含义，区分必要条件、充分条件和未确定条件。不同释义改变推导时，使用 `D1a`、`D1b` 等保留各分支。术语发生语义转换时分别编号。
3. **自然语言形式化（Formalize in Natural Language）**。以逻辑功能为单位编号，补全指代，保留适用范围、量词及其作用域、否定、模态、强度、时态和条件方向。保留条件句、析取句等作为完整命题所需的内部结构。注意因果与蕴涵、规范与事实、认识论与本体论的差异。符号逻辑用于确有帮助的检查或应用户要求提供。
4. **重构依赖（Reconstruct Dependencies）**。用 `P` 表示前提、`A` 表示局部假设、`C` 表示中间结论或目标结论。简单情形用 `P1`、`A1`、`C1`，复杂情形用 `Pa1`、`Aa1`、`Ca1`，下一子论证用 `Pb1` 等。按逻辑依赖排序，保留原文中可能的循环。上游结论已编号时，后续直接引用该 `C`。标清局部假设的起止与嵌套。需要把局部推导用于作用域外时，应用合适的假设撤销规则，引用相应子推导并注明撤销的 `A`。
5. **标注和验证（Annotate and Verify）**。按下文标注每个 `C`，检查其直接依赖和完整支持路线。最后在内部把重构还原成连贯自然语言并对照原文，检查是否遗漏实质内容或添加承诺，以及范围、强度、意图、支持关系是否改变。修正重构中的失真，保留原文中无法消除的歧义或断裂。仅在用户要求或发现实质差异时呈现有关往返结果。

## 前提与证据（Premises and Evidence）

- **明确前提（Explicit Premise）**。作者明确陈述或明确调用为当前依据的命题，允许忠实转述。对明确调用的命题附援引出处和核验状态。仅提及文献不足以表明调用。来源不可核验时，保留可确定的内容和引用，标明未核验。
- **隐含前提（Implicit Premise）**。仅在现有前提、定义、中间结论及适用规则不足时加入。根据文本依据、与已知相关理论承诺的相容性、作者理由的适用范围及所需支持强度选择最小充分补充。说明归属依据。单凭补入 `P → C` 可使推理有效，无法确立作者接受该命题。若个别或一般条件确获文本支持，按作者实际采用的范围写。多个合理方案有实质差异时分别呈现，归属未定的候选只放在相应候选分支。无法忠实补全时保留缺口。
- 某前提的含义、理由或理论作用不清楚时，先查提供的前文、明确援引处及同一著作相关章节，再按用户允许的范围考虑其他原典。区分作者实际调用的上游依据、仅可辅助解释的论述，以及使用情况未知的相关论证。找到实质性依赖时给出处和必要的上游推导。查无结果或无法获取时说明核验状态。作者作为公理或直接证成起点呈现的前提，保留其地位。
- 对作者实际诉诸的直接直观、自证性、直接经验等注明非推论性证成（Non-inferential Justification）。区分这些方式、未经说明的断言、公理设定和失败的推论。作为起点时按明确或隐含前提编号。作为目标结论时列 `C`，注明无推论性依据及作者诉诸的支持方式，规则和结构标为不适用。区分触发直接认知的情境与推论前提。遇到相互竞争的解释时，按文本证据保留实质分支。

## 结论标注（Conclusion Annotation）

每个 `C` 写出完整结论命题，并附以下四项。

| 字段 | 填写内容 |
| --- | --- |
| 依据（Grounds） | 直接依赖的 `D/P/A/C` 编号，独立路线分别列出。无依据时如实注明。 |
| 推理类型（Inference Type） | 如演绎（Deduction）、归纳（Induction）、溯因（Abduction）、类比（Analogy）或实际适用的其他类型。非推论性证成或无可确认的推理也可据实填写。 |
| 推理规则（Inference Rule） | 写真实匹配的规则名称，组合步骤按应用顺序写。无通行名称时描述支持关系。无适用规则时标明实际形式、无法确认或不适用。 |
| 论证结构（Argument Structure） | 链式（Serial）、联合（Linked）、汇聚（Convergent）、发散（Divergent）或单一（Simple）。可混合，证据不足时注明不确定，无适用结构时标明。 |

作者意图与实际推理不一致或无法确认是否一致时，另列意图推理（Intended Inference）与实际推理（Actual Inference）。对无效形式注明无效，保留作者尝试证明的结论。归纳、溯因等按其实际支持程度呈现。

出现断裂或条件性支持时，区分局部推导（Local Inference）和整体支持（Global Support）。某步可相对于直接依据有效，但每条经过未确立结论的路线均继承缺口，注明 `G1` 等来源及成立条件。逐条检查汇聚论证的独立路线，保留未受影响的支持。后续演绎步骤继承上游非演绎支持的不确定性。推导检查围绕依据与结论的关系，前提的真实性留给另行评价。

## 拆解粒度（Decomposition Granularity）

| 粒度 | 展开要求 |
| --- | --- |
| 一级：结构性拆解（Level 1 — Structural） | 保留主要命题和实质节点。可压缩无争议的连续步骤，仍注明依据与规则。 |
| 二级：严密拆解（Level 2 — Rigorous） | 默认级别。显化实质推导、隐含前提和局部假设，允许合并透明的基本规则组合。 |
| 三级：证明级拆解（Level 3 — Proof） | 对可形式化的推导逐步列基本规则、实例化与假设撤销。非演绎推理逐步说明证据、限制和支持关系。复杂或有争议的步骤可局部采用此级别。 |

满足所选粒度，且继续拆解无法澄清实质语义、承诺、上游来源、推导或诠释差异时停止。材料不足时保留未确定之处。证明级仍须完成所选证明系统要求的基本步骤。

## 报告语言与格式（Report Language and Format）

- 用户明确指定输出语言或图内标签格式时，按指定要求执行。默认按用户提问或任务指令的主要语言撰写报告。用户用英文提问时，标题、工作阶段、技术标签及推理术语均直接用英文。
- 中文拆解报告中，每次使用报告标题、工作阶段、技术标签及具体推理术语时，采用中文（English）格式和全角圆括号。使用通行英文术语，没有通行名称时用准确描述。命题正文、解释性自然语言、原文引语、人名、文献原题、公式和编号按其本来形式呈现。
- 通常依次呈现论证目标（Argument Objective）、相关定义（Definitions）、按依赖排序的论证及最终结论（Final Conclusion）。简单论证可合并章节。复杂论证用「子论证 A（Argument A）——具体目标」等标题。最终结论指明对应的 `C`，简述实质缺口或分支。原典研究为关键定义和命题给出可核验的位置，未知位置不填猜测值。内部质量检查无需附在报告后。

遇到含歧义、明确援引、假设撤销、断裂传递或非推论性证成的复杂情形，或需要对照完整标注格式时，读 [边界情形与示例](references/worked-cases.md) 的相应条目。
